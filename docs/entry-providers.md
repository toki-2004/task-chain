# APK 固定入口：免费服务商对比

> 目标：APK 里配一个**永远可达的固定网址**，它能告诉 APK 当前服务器的真实地址（重定向/配置指针），
> 这样即使后台换了地址（局域网 IP 变、启停穿透），手机端 App 也能自动恢复连接。

## 实现方式速览

> **v1.5 新增：局域网 UDP 自动发现（零账号零配置，已内置）**
> 服务器启动后监听 9875/UDP，APK 连不上或首次使用时在当前 WiFi 广播问询即可拿到服务器地址。
> 效果：**任何人和服务器连同一个 WiFi，装上 APK 打开就能连上，什么都不用填**，IP 怎么变都无所谓。
> 局限：只覆盖局域网（路由器开 AP 隔离时失效）；外网场景用下面的固定入口/隧道方案补。
> 若 Windows 防火墙拦截了 UDP 9875，在防火墙允许列表里放行 Python 即可。

| 方式 | 原理 | 固定程度 | 国内可用性 | 成本 |
| --- | --- | --- | --- | --- |
| **Gitee raw 配置文件**（本系统已原生支持） | 固定 URL 返回 `{"app_server_url": "..."}`，APK 读取后跳转 | ★★★ 永久 | ★★★ 直连 | 免费 |

## 推荐

### ① Gitee raw 配置文件（首选，已打通）

原理：Gitee 公开仓库放一个 `config.json`，内容是 `{"app_server_url":"http://当前地址:8000"}`。
APK 的「固定入口地址」填这个 raw 链接；后台改地址后点「立即推送」即可更新文件。

优点：Gitee 国内直连稳定、免费、无带宽焦虑（文件几十字节）、API 可自动推送（后台已集成）。
准备：注册 Gitee → 新建**公开**仓库 → 设置→私人令牌→生成（勾选 projects 权限）→
在后台「APK地址」标签页填入用户名/仓库名/文件路径/令牌 →「立即推送」。

### ② Tailscale（最省心，适合人在外的场景）

电脑和所有手机装 Tailscale 登录同一网络，每台设备获得**永久固定**的 100.x.x.x 虚拟 IP。
APK 服务器地址直接填电脑的虚拟 IP，在任何网络（流量/别的 WiFi）都能连，无公网暴露。
缺点：每台设备都要装 Tailscale 客户端并登录；偶尔走中继会慢。

### ③ 花生壳免费版（适合给完全不懂装 App 的人用）

运营商会给你一个**永久固定**的免费域名（隧道型），映射到本机 8000 端口，APK 地址直接填这个域名，
一辈子不变，也就不需要"自救"逻辑。缺点：免费版限速（约 1Mbps）、每月 1GB 流量，视频附件传输慢。

### 不推荐

- **natapp / cpolar 免费版**：域名随机且每次重启变化，违背"固定"初衷。
- **Cloudflare Workers/Pages、Vercel、GitHub raw**：国内基本不可达或不稳定。
- **短链服务**：政策风险高，随时失效。

## 组合建议（更新）

- 局域网用 → **UDP 自动发现已内置**，装上即连，什么都不用配。
- 外网用 → Tailscale（虚拟 IP 永久固定）或花生壳（固定域名）；两者地址都可以填进
  APK 源码的 `DEFAULT_ENTRY` 常量重新打包，实现任何人装上即连、零参数。
- 地址经常变、用户分散 → Gitee raw 方案（后台一键推送 + APK 固定入口跟读）。

- 纯局域网用 → 不需要固定入口，后台改地址 APK 会自动跟随（已有功能）。
- 偶尔外网用 → Tailscale（地址永久固定 = 天然的固定入口）。
- 要给别人用、地址可能变 → **Gitee raw 方案**（本系统后台已支持一键推送）。

> 安全提醒：配置文件里只有服务器地址一个字段，无敏感信息；但公网暴露服务本身前，
> 务必改掉弱密码并尽量上 HTTPS。
